X10 Android TV / Vendor Drop Brief / 2026-05-17

系统权限与厂商资料交付说明

目标是把当前普通 APK baseline，推进到可控的系统级投屏、OTA、诊断、硬件控制和量产运维。这里不再罗列长表，而是给厂商一个能直接执行的交付口径。

APP 已可验收 首页、APP 位、应用管理、DLNA 媒体接收、乐播兜底、best-effort 后台清理。
系统能力受阻 镜像投屏、冻结进程、静默 OTA、诊断日志、投影硬件控制需要系统身份。
先交 P0 五件 无线实物、工程固件、权限策略、投屏能力、vendor 接口包。
当前边界 P0 交付 P1 闭环 验收口径 资料包结构 发厂商话术

先把边界说清楚

当前 APK 已经可以作为普通 Android TV 应用继续验收，但下面这些系统级体验不能只靠普通 APK 承诺。厂商资料的核心价值，是把能力从“猜测能不能做”变成“接口、权限、固件、日志都可验证”。

当前 APP 能继续交付

普通 APK baseline

  • 首页、APP 位、应用管理、运行状态展示。
  • USB/本机 APK 的安装、升级入口和打开入口。
  • 自建 DLNA 媒体接收服务启动与 SSDP 多播发布。
  • 乐播 service-only 兜底，保持苹果/小米镜像入口可见。
  • 回首页后通过公开 API 尝试清理播放/商店后台进程。
不能靠普通 APK 保证

系统级能力阻塞

  • 苹果 AirPlay、安卓 Miracast / Wi-Fi Display 级镜像投屏。
  • 冻结或强杀系统包、顽固后台、预装商店进程。
  • 静默安装、静默 OTA、系统更新失败回滚。
  • 无 adb 场景导出 logcat、tombstone、投屏、音频和 OTA 日志。
  • 对焦、梯形、亮度、输入源、温度、风扇等投影硬件控制。

升级原则：只有拿到接口实体、测试固件、权限策略、sample、错误码和目标板运行日志后，对应能力才从 blocked 改为 development-ready。

P0：先交这五件

这五件是系统级联调的入场券。缺任何一件，后续都只能停留在普通 APK 层，无法给投屏、OTA、诊断和硬件控制做稳定承诺。

P0-01

无线模块实物确认

明确实物到底是 W800CS / W8800DCS 还是 8723DS，并提供 Wi-Fi/BT 驱动、固件、SDIO/UART 配置、天线说明和可复现日志。

P0-02

工程固件与刷机 SOP

提供当前测试固件、刷机工具、USB 驱动、Maskrom/Loader 进入方式、回滚流程、版本号和系统日志获取方式。

P0-03

系统身份与权限策略

明确普通 APK、priv-app、platform-signed app 各自权限边界，提供平台签名、权限白名单、SELinux policy 增量、预装与升级策略。

P0-04

投屏系统能力

说明 Miracast、Wi-Fi Display sink、Wi-Fi P2P、AirPlay sink、厂商投屏服务入口、设备名策略、投屏日志和错误码。

P0-05

vendor 接口包

提供 AIDL/JAR/AAR/SDK、接口文档、权限声明、错误模型、demo APK 或 sample client，以及接口在目标板跑通的日志。

验收方式

每件都要能独立复现

资料不是“口头支持”。我方必须能在测试机上刷入、安装、调用、失败重试，并拿到成功与失败日志。

P1：上线闭环资料

P0 让系统能力能开发，P1 让系统能力能上线、能排障、能售后。尤其 OTA 和诊断如果不闭环，后面批量铺设备会非常被动。

资料 厂商要给什么 缺失影响
OTA 机制与状态 API 升级类型、下载、校验、安装、重启、失败、回滚状态；调用接口；sample；错误码。 home 后台只能发布版本，设备侧不能形成可靠升级和回报闭环。
无 adb 日志导出 SOP logcat、dmesg、tombstone、ANR、投屏、音频、OTA 专项日志导出方式，最好附脚本或隐藏入口。 现场投屏、支付、升级、音频失败时，只能人工描述，不能定位。
投影硬件控制 API 自动/手动对焦、梯形校正、亮度、色彩模式、输入源、电源、温度、风扇、光机寿命。 首页和 AI 只能跳系统设置，不能做真正的设备级助手。
工厂测试与老化资料 Factory test APK/工具、Wi-Fi/BT/IR/USB/SIM/4G/音频/存储测试项、老化报告。 低端板批量稳定性没有证据，问题容易在量产后暴露。

从 blocked 到 development-ready

每个系统级能力都按同一套验收口径走。这样可以避免“厂家说支持，但我方 APK 调不通”的循环沟通。

1

接口实体

有 AIDL、JAR、AAR、SDK、系统 Intent 契约或可调用 service 名称。

2

权限说明

明确普通 APK、priv-app、platform-signed app 分别能不能调用。

3

测试固件

有明确版本号，可刷入、可回滚、能复现，接口版本和固件匹配。

4

sample 与日志

demo APK 或 sample client 能跑通，并提供成功、失败、超时日志。

验收项 通过标准 不通过时结论
接口文档 有方法、参数、返回值、权限、错误码、超时、生命周期说明。 不进入开发，只记录为资料缺口。
错误模型 不支持、权限不足、硬件忙、网络异常、服务未启动都有明确状态。 不承诺产品体验，只能做灰度实验。
生命周期 重启、进程被杀、网络切换、service 重启后能恢复或返回可解释错误。 不能进入量产默认开启。
日志闭环 现场无 adb 时仍可导出关键日志，能定位投屏、音频、OTA、权限失败。 不能作为售后可承诺能力。

可直接发给厂商的话术

请补充 X10 当前 Android TV 工程联调资料。我们当前普通 APK baseline 已能运行首页、APP 入口、应用管理、DLNA 媒体接收、乐播兜底和回首页后台清理。但系统级投屏、开机策略、OTA、日志诊断、投影硬件控制和低层资源管理，需要厂商提供系统资料后才能继续。

请优先提供：1. 实际 Wi-Fi/BT 模块确认，明确 W800CS/W8800DCS 与 8723DS 谁是实物；2. 当前工程固件、刷机工具、刷机 SOP 和回滚 SOP；3. 平台签名、priv-app、权限白名单、SELinux policy 和预装升级策略；4. Miracast / Wi-Fi Display / AirPlay sink 能力说明、vendor service 或系统入口、设备名策略和投屏日志路径；5. vendor 接口包，包含 AIDL/JAR/AAR/SDK、方法文档、错误码、demo APK 或 sample client、对应测试固件和目标板运行日志。

每个系统接口请同时说明普通 APK、priv-app、platform-signed app 各自可调用能力。不支持的能力请给明确错误码或状态，不要静默失败。
