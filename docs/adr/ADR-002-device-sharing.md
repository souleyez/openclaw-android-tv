# ADR-002: Share Platform Quota, Not Raw Upstream Keys

## Status

Accepted

## Date

2026-03-19

## Context

产品要求支持一个账号在多台设备上共享使用，同时希望在用户空闲时，把可用模型额度以池化方式调度给其他会话或设备。

如果直接把上游 API Key 暴露给用户或设备，会引发严重问题：

- 密钥泄露后无法控制滥用
- 难以按设备和会话做限流
- 无法安全回收权限
- 财务与审计难以闭环

## Decision

平台共享的是“平台配额与设备授权”，而不是“上游供应商真实密钥”。

设备侧只拿平台访问令牌。

平台内部通过租约机制把可用调用额度分配给会话或用户，但不会把真实 Key 下发到客户端。

## Consequences

### Positive

- 可安全控制共享设备数量
- 可按设备、账号、会话做限流
- 可随时撤销访问
- 可统一做账本和风险审计

### Negative

- 平台需要维护更复杂的授权与租约逻辑
- 池化调度逻辑需要谨慎设计，避免资源争用

## Alternatives Considered

### 方案 A：允许用户自带并共享真实上游 Key

未采纳。

原因：

- 泄露和滥用风险高
- 无法形成平台化商业模型

### 方案 B：每台设备独立分配一套上游 Key

未采纳。

原因：

- 运维成本高
- 不适合共享套餐

## Notes

MVP 阶段先做“账号设备上限 + 会话并发限制”，高级租约池化可在后续版本逐步增强。
