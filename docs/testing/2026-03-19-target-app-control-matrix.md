## 2. 文档目标

本矩阵用于指导 `Phase 0 PoC` 与 MVP 研发，明确首批目标 App 在低版本 Android / Android TV 环境下的控制可行性、推荐控制方式、权限需求、降级方案与测试重点。

## 3. 控制能力定义

### L1: App 级控制

- 打开 App
- 拉起到前台
- 返回首页
- 关闭或退出到后台

### L2: 通用播放控制

- 播放
- 暂停
- 继续
- 快进
- 快退
- 上一个
- 下一个
- 返回

### L3: 页面内复杂控制

- 搜索内容
- 选中具体节目
- 切换清晰度
- 切换账号
- 进入特定详情页

## 4. 控制链路优先级

所有目标 App 统一优先采用以下顺序：

1. `PackageManager + Intent / Deep Link`
2. `MediaSession / AudioManager / TransportControls`
3. `KeyEvent` 注入或系统级媒体按键
4. `AccessibilityService` 页面节点识别与导航

原则：

- 优先使用最稳定、最少权限的方案
- `AccessibilityService` 仅做兜底和个别 App 强适配，不作为默认主路径
- 复杂页面控制若稳定性不足，不进入 MVP 承诺范围

## 5. 总体适配结论

### 推荐作为 MVP 强适配对象

- Kodi
- VLC
- YouTube
- Spotify
- 系统设置

### 推荐作为 MVP 限制性支持对象

- Netflix
- 本地播放器

原因：

- Kodi 与 VLC 的控制接口和通用媒体行为更容易统一
- YouTube、Spotify 的基础控制通常可通过媒体会话或按键链路实现
- Netflix 页面内自动化与行为限制风险更高
- 本地播放器在不同厂商设备上的包名、能力和 Intent 入口差异较大

## 6. 逐 App 适配矩阵

## 6.1 YouTube

### 目标

- 支持快速打开 YouTube
- 支持播放、暂停、继续、返回、快进等通用控制

### 推荐控制方式

- L1：通过包名启动主 Activity
- L2：优先 `MediaSession`，次选 `KEYCODE_MEDIA_PLAY_PAUSE`、`KEYCODE_MEDIA_PLAY`、`KEYCODE_MEDIA_PAUSE`、方向键与返回键
- L3：仅做预研，不纳入 MVP

### 预期支持度

- L1：高
- L2：中高
- L3：低

### 主要风险

- 不同 TV 版本页面结构不同
- 页面搜索与内容选择依赖焦点位置，稳定性差

### 降级策略

- 若媒体会话失效，回退为按键控制
- 若快进快退不稳定，仅保留播放/暂停/返回

### PoC 验证重点

- 是否能在前台稳定接收媒体按键
- 是否能从首页可靠启动
- 遥控器方向键焦点行为是否一致

## 6.2 Netflix

### 目标

- 支持打开 Netflix
- 支持播放、暂停、继续、返回等基础控制

### 推荐控制方式

- L1：通过包名与 launcher activity 启动
- L2：优先媒体按键，次选返回/确认/方向键
- L3：不纳入 MVP

### 预期支持度

- L1：高
- L2：中
- L3：低

### 主要风险

- Netflix 对页面自动化与交互限制较多
- 媒体会话暴露行为可能因设备和版本不同而不稳定
- 登录态与区域差异可能导致页面结构不同

### 降级策略

- 仅承诺打开、暂停、继续、返回
- 快进/下一集若失败率高，则延后

### PoC 验证重点

- 播放中媒体按键是否稳定
- 从播放页返回上级页面是否可靠
- 不同 ROM 上是否能保持一致控制体验

## 6.3 Kodi

### 目标

- 支持完整的 L1 与大部分 L2
- 争取部分 L3，如简单导航与内容选择

### 推荐控制方式

- L1：启动主 App
- L2：优先 `MediaSession` 和 `KeyEvent`
- L3：优先原生支持或插件能力，次选 Accessibility

### 预期支持度

- L1：高
- L2：高
- L3：中

### 主要风险

- Kodi 版本差异和皮肤主题可能影响界面级导航

### 降级策略

- 若插件能力不可用，保留 L1/L2
- L3 仅在默认皮肤下提供实验性支持

### PoC 验证重点

- 播放控制是否能稳定响应
- 插件或协议调用是否可统一
- 不同皮肤下的导航差异

## 6.4 VLC

### 目标

- 支持打开、播放、暂停、继续、快进、快退、返回

### 推荐控制方式

- L1：包名启动或文件深链唤起
- L2：优先媒体会话，次选按键事件
- L3：不纳入 MVP

### 预期支持度

- L1：高
- L2：高
- L3：低

### 主要风险

- 文件来源不同会导致页面结构不同
- 某些定制 TV 盒子上的 VLC 版本较旧

### 降级策略

- 如果媒体会话不可用，保留方向键与确认键方案

### PoC 验证重点

- 本地视频播放状态下的控制稳定性
- 横屏播放器界面的焦点与按键行为

## 6.5 Spotify

### 目标

- 支持打开 Spotify
- 支持播放、暂停、继续、上一首、下一首

### 推荐控制方式

- L1：包名启动
- L2：优先 `MediaSession` / `TransportControls`
- L3：不纳入 MVP

### 预期支持度

- L1：高
- L2：高
- L3：低

### 主要风险

- 用户未登录时无法完成播放
- TV 端授权流程可能影响首次体验

### 降级策略

- 若用户未登录，返回明确提示而不是失败沉默
- 若自动播放失败，保留打开 App 与播放控制按钮提示

### PoC 验证重点

- 登录态下是否可稳定控制上一首/下一首
- 首次授权后的状态恢复是否正常

## 6.6 系统设置

### 目标

- 支持打开系统设置
- 支持返回、上下左右、确认等通用导航

### 推荐控制方式

- L1：通过系统 `Intent` 打开设置
- L2：通过 `KeyEvent` 与方向键导航
- L3：不纳入 MVP

### 预期支持度

- L1：高
- L2：中高
- L3：低

### 主要风险

- 不同厂商设置页结构完全不同
- Accessibility 节点结构差异大

### 降级策略

- 仅承诺“打开设置 + 通用方向/返回控制”
- 不承诺打开某个深层设置项

### PoC 验证重点

- 是否可稳定打开系统设置
- 不同 ROM 下方向键导航是否通用

## 6.7 本地播放器

### 目标

- 支持打开设备默认本地播放器
- 支持播放、暂停、继续、快进、返回

### 推荐控制方式

- L1：通过 Intent 匹配默认播放器或厂商白名单包名
- L2：优先媒体会话与按键事件
- L3：不纳入 MVP

### 预期支持度

- L1：中
- L2：中
- L3：低

### 主要风险

- 不同设备厂商的本地播放器差异极大
- 包名、Intent、媒体会话暴露行为不统一

### 降级策略

- 首期采用“白名单播放器”策略
- 对未知播放器只提供通用媒体按键尝试，不做功能承诺

### PoC 验证重点

- 主流盒子品牌默认播放器识别
- 播放状态下媒体按键接收率

## 7. 统一权限与系统能力要求

### 客户端建议接入的系统能力

- `RECORD_AUDIO`
- 前台服务
- `AccessibilityService`
- 媒体会话监听与媒体按键发送
- 网络权限
- 开机自启或保活策略支持

### 权限使用原则

- 非必要权限不默认申请
- `AccessibilityService` 必须做用户可理解说明
- 权限未开通时要提供明确引导与降级能力

## 8. 失败回退策略

### 回退优先级

1. 首选推荐链路执行
2. 若失败，尝试备用链路一次
3. 若仍失败，给用户展示明确字幕反馈
4. 记录日志，进入适配统计

### 用户提示规范

- “已打开 YouTube”
- “已暂停播放”
- “当前应用暂不支持该操作”
- “请先登录 Spotify 再尝试播放”
- “当前设备未开启辅助控制权限”

## 9. PoC 验证优先顺序

建议按以下顺序验证：

1. VLC
2. Kodi
3. Spotify
4. YouTube
5. 系统设置
6. Netflix
7. 本地播放器

原因：

- 先验证最容易成功且控制价值高的播放器
- 再验证高频视频 App
- 最后处理最不稳定的 Netflix 与厂商本地播放器

## 10. PoC 通过标准

每个目标 App 的 PoC 至少要验证以下项目：

- 能否稳定启动
- 能否在播放态下响应暂停/继续
- 能否从前台播放页返回
- 异常时是否能正确提示
- 低版本 Android TV 是否行为一致

推荐通过门槛：

- L1 成功率 >= 95%
- L2 成功率 >= 85%
- 平均响应时间 <= 4 秒

## 11. 研发建议

### 第一批进入正式开发的 App

- VLC
- Kodi
- Spotify
- YouTube
- 系统设置

### 第二批视 PoC 结果决定

- Netflix
- 本地播放器

### 实施建议

- 为每个 App 单独建立 `ControlProfile`
- 每个 `ControlProfile` 包含：
  - 包名
  - 启动方式
  - 支持动作集
  - 权限依赖
  - 回退链路
  - 设备白名单
  - 失败日志标签
