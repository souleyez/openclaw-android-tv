## 2. 产品概述

OpenClaw Android / Android TV Assistant 是一个面向低版本 Android 与 Android TV 设备的 AI 语音助手产品。用户可通过语音与屏幕大字字幕交互，控制电视上的常用 App 启停、节目播放、系统设置切换，并通过订阅或 Token 充值方式使用后台大模型能力。

本产品首期以电视与盒子场景为主，兼顾手机端调试或陪伴场景。核心价值不是通用聊天，而是“低门槛电视控制 + 多语言语音交互 + 可运营订阅体系”。

## 3. 产品目标

### 3.1 商业目标

- 在 Android TV 与电视盒子场景中提供可订阅的 AI 语音控制服务
- 通过订阅制与 Token 充值制覆盖模型调用成本
- 支持家庭共享与多设备复用，提高单用户生命周期价值

### 3.2 用户目标

- 不用手动找遥控器层层操作，直接说话控制电视
- 支持中文、英语、西班牙语、土耳其语、俄语等多语言交互
- 在电视上获得清晰的大字字幕反馈和角色化陪伴感

### 3.3 MVP 目标

- 让用户在 Android TV/盒子上完成以下闭环：
  - 安装并登录
  - 绑定账号
  - 通过语音控制指定 App
  - 对播放内容做暂停、继续、返回、快进等操作
  - 看到大字字幕与角色反馈
  - 完成订阅或充值
  - 在多台设备上共享使用

## 4. 背景与机会

现有 Android TV/盒子系统普遍存在以下问题：

- 遥控器操作链路长，搜索和切换内容效率低
- 多语言家庭成员使用成本高
- 部分低版本系统 UI 复杂，老年用户不友好
- 第三方内容 App 各自割裂，用户无法用统一语音方式控制

机会点在于：如果产品能在低版本安卓电视设备上稳定运行，并优先覆盖高频 App 的通用控制动作，就有机会建立一个“跨 App 的电视语音入口”。

## 5. 目标用户

### 5.1 核心用户

- 海外华人家庭用户
- 使用 Android TV 或电视盒子的家庭用户
- 希望简化老人和儿童电视操作的家庭
- 需要多语言语音控制的国际用户

### 5.2 次级用户

- 本地播放器、Kodi、VLC 的重度用户
- 需要用电视做音乐播放的用户
- 将电视作为客厅语音终端的技术爱好者

### 5.3 非目标用户

- 只想在手机端做纯聊天的用户
- 强依赖 Apple TV / Fire TV 非安卓体系的用户
- 对全量智能家居联动有强需求的企业用户

## 6. 用户场景

### 场景 1：快速打开目标 App

用户说：“打开 YouTube。”

期望结果：

- TV 端直接启动 YouTube
- 角色提示“已为你打开 YouTube”
- 屏幕显示大字字幕

### 场景 2：控制视频播放

用户说：“暂停。”

期望结果：

- 当前前台播放器暂停
- 大字字幕显示“已暂停”
- 若无法控制，提示“当前 App 不支持该动作”

### 场景 3：控制音乐 App

用户说：“打开 Spotify 并播放。”

期望结果：

- 启动 Spotify
- 尝试发起播放动作
- 如 App 需要用户先完成授权，则给出明确提示

### 场景 4：系统设置切换

用户说：“打开系统设置。”

期望结果：

- 进入设置页
- 可继续支持“返回”“向下”“确定”等基础操作

### 场景 5：老人用户看字幕操作

用户听不清播报或环境嘈杂时，可直接看电视大字字幕理解系统反馈。

### 场景 6：家庭共享

一个家庭账号在客厅电视、卧室盒子、备用投影设备上共享使用一个订阅。

## 7. 目标 App 范围

MVP 首批重点适配 App：

- YouTube
- Netflix
- Kodi
- VLC
- Spotify
- 系统设置
- 本地播放器

### 7.1 控制能力分级

为控制预期可管理，定义三层能力：

- L1：启动/关闭/切到前台
- L2：播放/暂停/继续/快进/返回/下一集等通用控制
- L3：页面内复杂操作，如搜索、切换账号、选集、切换清晰度

### 7.2 MVP 支持边界

- YouTube：优先支持 L1 + L2，L3 仅保留搜索入口预研
- Netflix：优先支持 L1 + L2，L3 暂不承诺
- Kodi：支持 L1 + L2，部分 L3 可通过原生接口或插件增强
- VLC：支持 L1 + L2
- Spotify：支持 L1 + L2，播放前提受用户登录状态影响
- 系统设置：支持 L1，部分通用导航动作支持 L2
- 本地播放器：支持 L1 + L2，具体按设备厂商播放器能力适配

## 8. 产品定位

### 8.1 一句话定位

一个能在 Android TV 上“听得懂、控得动、看得清、可订阅”的 AI 电视语音助手。

### 8.2 差异化

- 面向低版本 Android 与 Android TV
- 强调跨 App 通用语音控制，而不是单一播放器语音助手
- 支持多设备共享
- 具备后台模型路由与成本控制能力
- 大字字幕与虚拟形象适合电视客厅场景

## 9. 功能范围

### 9.1 客户端核心功能

#### 9.1.1 语音输入

- 支持按键触发语音输入
- 支持多语言识别
- 支持网络异常和识别失败提示
- 支持识别中状态展示

#### 9.1.2 大字字幕输出

- 所有系统反馈默认显示为大号字幕
- 支持字幕显示时长配置
- 支持中英文及多语言显示

#### 9.1.3 虚拟形象

- 首期提供多个 2D 角色
- 可选择男声、女声、老人声、儿童风格角色
- 角色切换不影响订阅状态和设备绑定

#### 9.1.4 App 控制

- 打开 App
- 切换前台 App
- 返回首页
- 播放、暂停、继续
- 快进、快退
- 上一个、下一个
- 返回
- 基础方向键与确定操作

#### 9.1.5 账号与订阅

- 注册/登录
- 查看当前订阅状态
- 查看 Token 余额
- 查看绑定设备数量
- 支持升级订阅和充值

#### 9.1.6 设备共享

- 一个账号绑定多台设备
- 可查看设备列表
- 可移除设备
- 超过设备上限时引导解绑旧设备或升级套餐

#### 9.1.7 OTA 升级

- 支持检测版本更新
- 支持提示用户安装新版本
- 支持后台灰度开关控制是否可见

### 9.2 后端核心功能

#### 9.2.1 用户与设备管理

- 账号创建
- 设备注册
- 设备绑定与解绑
- 设备在线状态记录

#### 9.2.2 订阅与充值

- 月订阅
- 年订阅
- Token 充值包
- 信用卡支付
- 稳定币支付接口预留

#### 9.2.3 模型路由

- 对接多个模型供应商
- 按成本、稳定性、区域可用性动态路由
- 记录每次调用日志与成本

#### 9.2.4 OTA 管理

- 创建版本发布任务
- 设定区域、时段、设备组
- 回滚或暂停发布

#### 9.2.5 财务后台

- 查看订单流水
- 查看充值流水
- 查看 Token 消耗
- 查看模型供应商成本
- 查看毛利估算

## 11. 用户流程

### 11.1 首次使用流程

1. 安装 App
2. 进入欢迎页
3. 登录或注册
4. 选择语言和角色
5. 完成必要权限授权
6. 绑定设备
7. 进入首页
8. 尝试第一条语音指令

### 11.2 语音控制主流程

1. 用户按下语音键
2. App 开始录音
3. 识别语音文本
4. 意图解析
5. 执行 App 控制或系统动作
6. 返回执行结果
7. 用语音和字幕反馈结果

### 11.3 订阅充值流程

1. 用户进入会员页
2. 选择套餐或充值包
3. 发起支付
4. 支付成功
5. 后端更新账户状态
6. 客户端同步订阅与余额

### 11.4 设备共享流程

1. 用户在第二台设备登录
2. 系统检测设备数
3. 若未超限则直接绑定
4. 若超限则提示解绑旧设备或升级套餐

## 13. 订阅与计费方案

### 13.1 计费模式

- 基础订阅：按月或按年
- Token 充值：针对高频或高级模型调用
- 家庭共享：根据套餐决定可绑定设备数

### 13.2 推荐套餐结构

- 基础版：1 台设备，基础语音控制，有限 Token
- 家庭版：3 台设备，共享额度，优先支持 TV 场景
- 高级版：5 台以上设备，更高 Token 配额，更优先模型

### 13.3 扣费策略

- 通用控制指令优先走低成本模型或规则引擎
- 聊天与复杂问答消耗 Token
- 高成本模型需按策略限制使用频次

## 15. 非功能需求

### 15.1 兼容性

- 最低支持 Android 7.0+
- 支持 Android TV 遥控器导航
- 支持无 GMS 设备降级运行

### 15.2 性能

- 主界面启动时间低于 3 秒
- 指令执行目标延迟 2 至 4 秒
- 字幕显示延迟小于 800ms

### 15.3 可用性

- 焦点可见
- 字体足够大
- 弱网下有明确反馈
- 动作失败时给出可理解提示

### 15.4 安全

- 不在客户端暴露上游模型密钥
- 设备授权可撤销
- 所有计费和调用行为可审计

## 16. 风险与边界

### 16.1 高风险项

- Netflix、YouTube 等第三方 App 的页面内复杂控制并不稳定
- 低版本定制 TV ROM 的权限与后台策略差异大
- 无 Google 服务设备的 ASR/TTS 质量可能不一致

### 16.2 产品边界

- MVP 不承诺所有 App 的页面内搜索和选集
- MVP 不承诺所有 ROM 上完全一致的控制效果
- 复杂控制失败时要优先回退到通用导航或明确提示
